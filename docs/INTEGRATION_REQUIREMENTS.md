# Research Trace：需求复核与框架集成

日期：2026-09-03。依据：用户本次要求、`REQUIREMENTS.md`、`DESIGN.md`、当前代码和更新记录。

后续方向更新：用户进一步明确要求尽可能用成熟框架替换自研功能。本文记录 alpha.21 的首轮增量集成；下一阶段以 [框架替换审计](FRAMEWORK_REPLACEMENT_AUDIT.md) 为选型依据，不再将现有中央存储、认证、协议和 UI 基础设施视为必须保留的实现。

这份文件将原有需求映射到可验证的集成行为。原需求中已经确认的产品规则继续有效；新增功能的优先顺序会随用户补充的实际痛点调整。

## 用户要完成的工作

1. 在 Claude Code、Codex CLI / Desktop 中正常做科研，不额外维护一套流水账。
2. 以后能找回一个数字、决定、失败路线的来源，知道当时依据了什么。
3. 日常阅读看到有价值的研究记录；需要核对时能展开原始过程。
4. 用并列研究线组织项目，保留跨阶段的讨论、论文、数据、实现、实验和结论。
5. 人能修改、确认、纠正 AI 整理的内容，旧版本和依据仍然可查。
6. 团队、多电脑和 HPC 使用同一个项目身份，断网或进程退出后能继续投递。
7. 容易启用、暂停、迁移和恢复；集成故障不能中断研究工作。

## 产品规则

| 需求 | 实现必须保持的行为 |
| --- | --- |
| 日常入口 | Project → Overview / Chapters → 通用 Node；附件、来源和评论附着在记录上 |
| 研究线 | Chapter 由人定义；Chapter 之间没有推断的时间或父子关系 |
| 原始与精选 | 原始事件永久保留；无价值 batch 可以不创建 Node |
| 人工权威 | 机器不能自我确认、覆盖人的新版本或悄悄关闭 correction |
| 明确证据 | 每次导入保留提供方、来源 ID、内容摘要校验和；不编造作者、结论或数据依赖 |
| 权威来源 | 中央服务持有研究记录及修订；外部索引是可重建的派生数据 |
| 启用范围 | 项目显式绑定；外部框架只处理显式配置的项目 |
| 恢复能力 | 幂等、后台重试、失败可见；旧数据和备份格式继续可读 |
| 接口 | 保留六个研究 MCP 工具；框架集成不要求 Agent 同时学习多套产品流程 |

## 选用现有框架的边界

### MLflow：实验与执行证据

通过官方客户端读取 run / trace，将原始来源作为有版本的证据进入原始历史，并允许关联到已有 Node。run 的参数、指标、数据集与 trace 的嵌套调用保留结构；不把每次 run 自动升级为研究结论。

接入配置明确绑定 Research Trace 项目与 MLflow experiment。服务器地址由部署者配置，请求只能选择已有连接，不能让任意调用者指定服务器地址。外部源无法访问时，已保存的证据副本仍然能查看。

MLflow 已有 Claude Code 可靠追踪机制，可作为后续采集来源。替换现有 Hook 前，须验证项目 opt-in、原文范围、隐藏推理过滤、退出/断网重放和 source ID，不能仅凭同为 tracing 就宣布等价。

### Basic Memory：项目知识的派生检索

通过官方 MCP 协议同步项目总结、研究线摘要和精选记录，让 Basic Memory 承担全文/语义/混合检索。同步副本位于明确的生成目录，带中央记录 ID、版本和来源元数据。

检索命中必须重新解析到中央当前记录；不能把过期的索引文本、外部项目的笔记或已删除的记录直接作为权威结果。中央人工修订仍然优先，外部检索不可用时回退到本地搜索并显示状态。

原始 transcript 默认不进入知识索引，避免把低价值操作铺满日常检索。部署方可单独选择 Basic Memory 的模型与存储配置。

### 其余框架

- Claude-Mem：其记忆注入与检索方式可作参考；先避免再运行一个职责相同的 Recorder。
- Entire：适合随后以明确 checkpoint 引用关联代码证据，不强迫科研过程每轮 commit。
- AiiDA：只有需要改造计算工作流时再接入，其 provenance 图可以作为证据来源。
- Graphiti：只有需要超出明确 parent / artifact 关系的时序知识查询时再引入；推断的知识边不能冒充已验证的数据流。

## 首轮集成验收

1. 使用真实 MLflow 客户端读取测试 run 和 trace，保留结构并关联到指定项目/记录。
2. 重复导入相同来源内容不产生重复证据；来源更新时留下新的不可变快照。
3. 不允许把未绑定 experiment 的内容导入另一个项目。
4. 使用真实 Basic Memory 服务写入和检索精选记录，不以手写 JSON 模拟成功。
5. 人修改中央记录后，检索返回中央新版本；外部返回的未知 ID 不进入结果。
6. 框架不可用时，项目读取、记录、已有搜索和原始投递仍能使用，状态明确显示失败。
7. 集成不能赋予机器 human 权限，不更改既有确认与纠正规则。
8. 提供可运行的本地演示配置和部署步骤，明确哪些功能已经验证、哪些仍未接入。

## 已发现的基线问题

- alpha.26 以前曾使用主会话 fork Recorder；alpha.27 已统一为独立订阅会话、持久批次与程序写入。
- 当前搜索的 semantic scope 指精选记录层，SQL 实现仍是 LIKE；不应称为向量语义搜索。
- Codex 自动采集、团队映射管理页面等仍是原基线的未完成功能；接通外部框架本身不等于完成这些验收项。
- Windows 初始基线运行：298 通过、5 失败；失败涉及长路径、路径表示差异及 Node 输出的默认 GBK 解码。与后续新增回归分别记录。
- 改用工作区内短临时路径和 UTF-8 模式后，完整回归 313 项通过；真实 MLflow / Basic Memory 模拟数据验证也通过。此结果不等于生产部署或中文领域召回质量已经验收。
